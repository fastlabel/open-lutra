# Directory Structure

> Describes where things live and the conventions each layer follows. File-level detail is
> deliberately omitted — the tree itself is the source of truth for individual files.
> Update this document when adding a new top-level directory, feature, or convention.

## Project Root

```
open-lutra/
├── backend/                    # Backend (FastAPI, Bulletproof pattern)
│   ├── pyproject.toml          # Python settings (ruff / mypy / pytest / coverage)
│   ├── uv.lock                 # uv lockfile
│   ├── app/                    # Python package (source)
│   └── tests/                  # Backend tests (mirrors backend/app/)
├── frontend/                   # Frontend (React + Vite, Bulletproof React)
├── simulator/                  # Development simulator (see simulator/README.md)
├── config/                     # Recording configs (YAML; selected via RECORDING_CONFIG)
├── docs/                       # Documentation
├── examples/                   # Reference snippets (e.g. custom ROS2 message types)
├── .devcontainer/              # Dev Container settings
├── .local/                     # Local materials (gitignored)
├── docker-compose.yml          # Development environment
├── docker-compose.prod.yml     # Production overrides
├── Dockerfile                  # Backend image
├── Makefile                    # Command collection
└── .env                        # Environment variables (gitignored)
```

## Backend (`backend/app/`)

Each feature under `features/` follows the same file conventions:

| File | Responsibility |
|---|---|
| `router.py` | API endpoints (HTTP glue; excluded from coverage) |
| `service.py` | Application service / orchestration |
| `models.py` | Domain models with business logic |
| `schemas.py` | API request/response schemas (pydantic; no default values) |

Not every feature needs every file, and larger features add purpose-named modules
(e.g. `scanner.py`, `runner.py`, `writer.py`) or subpackages.

```
backend/app/
├── main.py          # FastAPI entry point, lifecycle management
├── settings.py      # pydantic-settings configuration + recording-config loader
├── dependencies/    # FastAPI Depends (DI, path validation, exception handlers)
├── features/        # Feature domains (Bulletproof pattern)
│   ├── recording/       # Recording start/stop/status (ROS2BagRecorder subprocess)
│   ├── topics/          # Topic monitoring, SSE streams
│   ├── recordings/      # Recording directory operations (list / rename / delete / meta)
│   ├── analysis/        # Post-recording analysis (quality_report.json / timeline_data.json)
│   ├── media/           # Preview data generation (MP4 via ffmpeg / Joint time series)
│   ├── jobs/            # Background job queue (asyncio.Queue + single worker + SSE)
│   ├── validation/      # Per-recording rule checks (builtins/ + custom/ + registry)
│   ├── upload/          # Recording → zip → UploadDestination (destinations/ backends)
│   ├── lerobot_export/  # MCAP → LeRobot v3.0 dataset writer (parquet + MP4)
│   └── config/          # System configuration, memory info
├── infra/           # Infrastructure layer
│   ├── mcap/            # Shared MCAP I/O (reader, timestamp normalization, structure detection)
│   └── ros2/            # ROS2-related (rclpy node, CLI wrapper, QoS overrides, pty record process)
└── shared/          # Modules shared across multiple features (log manager, header.stamp utility)
```

## Frontend (`frontend/src/`)

Each feature under `features/` exposes its public API through an `index.ts` barrel
(direct `@/features/*/*` imports are a Biome error). Inside a feature: the main
component at the top level, small UI parts in `ui/`, state in `store.ts` (Zustand),
and feature-local hooks/utilities alongside them.

```
frontend/src/
├── App.tsx / main.tsx     # TanStack Router initialization / ReactDOM entry point
├── api/
│   ├── fetch-client.ts    # Custom fetch client (orval mutator)
│   └── generated/         # Auto-generated by orval per API tag (do not edit)
├── features/              # Feature domains (Bulletproof React)
│   ├── recording/         # Recording controls (record button, timer, sounds)
│   ├── live-topics/       # Live topic quality monitoring + preview
│   ├── monitor/           # Quality charts + logs
│   ├── quality-summary/   # Static summary of the quality report
│   ├── quality-timeline/  # Timeline visualization (heatmap, video, graphs)
│   ├── recordings/        # Recording list panel
│   ├── recordings-table/  # Recordings table (/recordings page)
│   ├── settings/          # Task-name and pre-registered-metadata editors
│   ├── validation/        # Validation summary panel + row badge
│   ├── upload/            # Upload buttons + row badge
│   └── lerobot-export/    # LeRobot export dialog + bulk-export button
├── components/
│   ├── layout/            # Header, StatusBar (dev mode only), job pill, logo mark
│   └── ui/                # shadcn/ui primitives
├── hooks/                 # Shared hooks (use-api, SSE streams, upload status)
├── lib/                   # Shared utilities (format, topic-sort, query client/keys, ...)
├── stores/                # Shared Zustand stores (used by multiple features)
└── routes/                # TanStack Router page definitions
    ├── __root.tsx              # Root layout (QueryClientProvider, Header, StatusBar)
    ├── index.tsx               # Recording page (/)
    ├── recordings.tsx          # Recordings list page (/recordings)
    └── recordings_.$folder.tsx # Recording detail page (/recordings/:folder)
```

## Tests

### Backend (`backend/tests/`)

Mirrors the `backend/app/` directory structure: `backend/app/features/<x>/<y>.py`
is tested by `backend/tests/features/<x>/test_<y>.py`. Shared fixtures live in a
`conftest.py` at the matching level.

### Frontend

```
frontend/src/
├── __mocks__/zustand.ts                          # Zustand auto-reset mock
├── test/setup.ts                                 # MSW server startup / reset
├── test/test-utils.tsx                           # render with QueryClientProvider
├── mocks/server.ts                               # MSW server (orval-generated handlers)
├── lib/__tests__/*.test.ts                       # Unit tests for utilities
├── hooks/__tests__/*.test.tsx                    # Unit tests for hooks
├── stores/__tests__/*.test.ts                    # Unit tests for shared stores
└── features/{feature}/__tests__/*.test.ts        # Feature-specific unit tests
```
